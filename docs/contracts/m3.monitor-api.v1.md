# M3 版本监控 Web API 契约

> 状态：Phase 5 冻结
> 日期：2026-08-10

## 1. 变更请求与幂等

所有 POST/PATCH 请求体严格拒绝未知字段并携带 UUID `request_id`。该 ID 在 M3 数据库内全局唯一；相同 method、target 和规范 payload 重放返回首次结果且不重复副作用，同一 ID 用于不同请求返回 409 `MONITOR_IDEMPOTENCY_CONFLICT`。命令事实与业务迁移持久化，进程崩溃后可完成或重放首次命令。

- 创建：`m3.monitor-task-create.request.v1`，只接受 name、endpoint_id、effective_at、end_at、daily_trigger_time；
- 修改：`m3.monitor-task-patch.request.v1`，完整替换 daily_trigger_time 与 end_at；
- 生命周期/调度命令：`m3.monitor-command.request.v1`；
- 人工重试：`m3.monitor-run-retry.request.v1`。

固定 endpoint、分支身份、effective_at 和 timezone 不可修改。PATCH 只允许 active、scheduler_error、paused；暂停时修改在恢复后生效。archive 仅允许 ended 且不存在 queued/running Run，归档后只读且不可重试。人工 retry 仅允许 failed Run，返回 202，后台复用原 run 和区间。

## 2. 查询

- task/list/runs 使用内容 ETag；列表默认 `created_at DESC, task_id DESC` 且隐藏 archived；
- run 列表使用严格 `m3.monitor-run-list.v1`；
- endpoint options 使用 `m3.monitor-endpoint-options.v1`，只含 endpoint_id/label；
- 历史报告只按 run_id 读取，30 天后返回 410；
- task latest 报告按 task_id 读取，永久可读，且不因最近 Run 失败而变化；
- 报告读取重新校验 task/run/publication 归属与 SHA，不接受路径或客户端 report_ref。

## 3. 创建与调度

endpoint_id 必须来自已启用注册表。服务端解析并冻结 URL、仓库 UUID、仓库相对路径、bound Revision 和 copy boundary；创建前验证 endpoint、分支身份、生效时间 Revision 与 dataset_layout 可装配。单工作簿未来解析失败不阻断创建。

`pending_run_count` 统计已到期且状态为 queued/running 的 Run。scheduler-sync 是显式检查并修复到期望定义；普通列表轮询不逐项访问 Windows Task Scheduler。

## 4. 错误与安全

错误固定为 `{"error":{"code":"MONITOR_*","message":"脱敏中文摘要"}}`，无 details、路径、凭据、stderr、异常或堆栈。HTML 使用发布 SHA 作为 ETag，并设置 nosniff、禁止 framing 和严格 CSP。
