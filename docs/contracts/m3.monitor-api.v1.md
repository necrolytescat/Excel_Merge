# M3 版本监控 Web API 契约

> 状态：Phase 5 冻结
> 日期：2026-08-10

## 1. 变更请求与幂等

所有 POST/PATCH 请求体严格拒绝未知字段并携带 UUID `request_id`。该 ID 在 M3 数据库内全局唯一；相同 method、target 和规范 payload 重放返回首次结果且不重复副作用，同一 ID 用于不同请求返回 409 `MONITOR_IDEMPOTENCY_CONFLICT`。命令事实与业务迁移持久化，进程崩溃后可完成或重放首次命令。

- 创建：`m3.monitor-task-create.request.v1`，只接受 name、endpoint_id、effective_at、end_at、daily_trigger_time；
- 修改：`m3.monitor-task-patch.request.v1`，完整替换 daily_trigger_time 与 end_at；
- 生命周期/调度命令：`m3.monitor-command.request.v1`；
- 人工重试：`m3.monitor-run-retry.request.v1`。

固定 endpoint、分支身份、effective_at 和 timezone 不可修改。PATCH 只允许 active、scheduler_error、paused；暂停时修改在恢复后生效。archive 仅允许 ended 且不存在 queued/running Run，归档后只读且不可重试。人工 retry 仅允许 failed Run，返回 202，后台复用原 run 和区间。

写接口成功响应冻结如下：

| 接口 | HTTP | 响应 |
|---|---:|---|
| POST /api/monitor/tasks | 201 | m3.monitor-task.v1 |
| PATCH /api/monitor/tasks/{task_id} | 200 | m3.monitor-task.v1 |
| POST pause/resume/end/archive/scheduler-sync | 200 | m3.monitor-task.v1 |
| POST /api/monitor/runs/{run_id}/retry | 202 | m3.monitor-run-retry.accepted.v1 |

retry 的 202 表示持久化 intent 已提交，不表示已启动 OS 进程。系统使用持久化 outbox 至少一次派发，Web 启动和后台恢复扫描未完成 intent；Run claim、attempt 和报告发布保持幂等。系统不承诺 OS 进程 exactly-once。

## 2. 查询

- task/list/runs 使用内容 ETag；列表默认 `created_at DESC, task_id DESC` 且隐藏 archived；
- run 列表使用严格 `m3.monitor-run-list.v1`；
- endpoint options 使用 `m3.monitor-endpoint-options.v1`，只含 endpoint_id/label；
- 历史报告只按 run_id 读取，30 天后返回 410；
- task latest 报告按 task_id 读取，在任务未被彻底删除前可读，且不因最近 Run 失败而变化；
- 报告读取重新校验 task/run/publication 归属与 SHA，不接受路径或客户端 report_ref。

查询路由冻结：

- GET /api/monitor/endpoint-options；
- GET /api/monitor/tasks、GET /api/monitor/tasks/{task_id}；
- GET /api/monitor/tasks/{task_id}/runs；
- GET /api/monitor/runs/{run_id}/report；
- GET /api/monitor/tasks/{task_id}/latest-report。

JSON 响应 ETag 为规范 JSON 投影的 SHA-256 强标签 "hex"。task 使用完整响应；task list/run list 排除顶层 as_of 后计算，避免观察时间造成无效刷新。If-None-Match 对同值强标签和 W/"hex" 均返回 304，304 不含响应体。报告 HTML 以发布时 HTML SHA-256 生成强标签，并采用相同条件请求规则。

## 3. 创建与调度

endpoint_id 必须来自已启用注册表。服务端解析并冻结 URL、仓库 UUID、仓库相对路径、bound Revision 和 copy boundary；创建前验证 endpoint、分支身份、生效时间 Revision 与 dataset_layout 可装配。单工作簿未来解析失败不阻断创建。

`pending_run_count` 统计已到期且状态为 queued/running 的 Run。scheduler-sync 是显式检查并修复到期望定义；普通列表轮询不逐项访问 Windows Task Scheduler。同步修复失败仍返回 200 当前 m3.monitor-task.v1，由 status=scheduler_error、sync_status=error/drifted 和脱敏 MONITOR_SCHEDULER_SYNC_FAILED 表达。archived 任务业务只读，但允许 scheduler-sync 修复系统任务 removal。

## 4. 错误与安全

错误固定为 `{"error":{"code":"MONITOR_*","message":"脱敏中文摘要"}}`，无 details、路径、凭据、stderr、异常或堆栈。允许值与 HTTP 映射：

| HTTP | code |
|---:|---|
| 400 | MONITOR_INVALID_REQUEST、MONITOR_INVALID_CURSOR |
| 404 | MONITOR_ENDPOINT_NOT_FOUND、MONITOR_TASK_NOT_FOUND、MONITOR_RUN_NOT_FOUND、MONITOR_REPORT_NOT_FOUND |
| 409 | MONITOR_ENDPOINT_DISABLED、MONITOR_BRANCH_CONFIGURATION_INVALID、MONITOR_DATASET_CONFIGURATION_INVALID、MONITOR_STATE_CONFLICT、MONITOR_IDEMPOTENCY_CONFLICT |
| 410 | MONITOR_REPORT_EXPIRED |
| 500 | MONITOR_API_INTERNAL_ERROR |
| 503 | MONITOR_SERVICE_UNAVAILABLE |

分支身份、copy boundary 或 effective Revision 无效使用 MONITOR_BRANCH_CONFIGURATION_INVALID；dataset layout 无法装配只使用 MONITOR_DATASET_CONFIGURATION_INVALID。SVN timeout、认证失败或 Provider 不可用统一脱敏为 MONITOR_SERVICE_UNAVAILABLE。

HTML 使用发布 SHA 作为 ETag，并设置 nosniff、禁止 framing 和严格 CSP。
