# `m3.monitor-task.v1` 版本监控任务契约

> 状态：Phase 0 冻结
> 日期：2026-08-10
> Schema：`app/schemas/monitor.py::MonitorTaskPayload`

## 1. 用途与边界

该契约是单个监控任务的公开权威表示，覆盖固定分支、业务状态、调度配置、Windows 调度同步状态和最近一次运行摘要。它不复用或修改 `m2.batch.v1`、`m2.diff.v1`。

每一级对象严格拒绝未知字段；枚举区分大小写；计数和 Revision 是严格整数。所有瞬时时间输入必须携带时区，模型统一规范为 UTC RFC 3339 `Z`；每日触发时间是 `Asia/Shanghai` 的无时区本地墙上时间，精确到秒。

完整规范示例见 `m3.monitor-task.v1.example.json`。

## 2. 顶层字段

| 字段 | 规则 |
|---|---|
| `schema_version` | 固定 `m3.monitor-task.v1` |
| `task_id` | 服务端 UUID |
| `name` | 1..128 字符的公开任务名 |
| `status` | 任务业务状态，见第 5 节 |
| `branch` | 创建后不可修改的固定分支公开身份 |
| `schedule` | 生效、结束、每日触发和下一逻辑截止点 |
| `scheduler` | 与业务状态分开保存的调度期望和同步事实 |
| `latest_run` | 最近一次逻辑截止点摘要；可为空 |
| `last_runner_heartbeat_at` | 最近公开 Runner 心跳；可为空 |
| `created_at` / `updated_at` | UTC 权威时间，且 `updated_at >= created_at` |
| `paused_at` / `ended_at` / `archived_at` | 对应生命周期状态的 UTC 时间；不适用时为空 |

## 3. 固定分支

`branch` 只公开：

- `endpoint_id` 和公开 `label`；
- `repository_uuid`；
- 规范仓库相对路径 `repository_relative_path`；
- 创建时验证的 `bound_revision` 和 `copy_boundary_revision`。

相对路径不以 `/` 开始或结束，不含反斜杠、空段、`.` 或 `..`。`copy_boundary_revision <= bound_revision`。公开契约不含 canonical URL、SVN 凭据、仓库根 Revision 清单或缓存位置；内部服务仍须用冻结 canonical URL 重新校验绑定身份。

## 4. 调度与时间

`schedule`：

| 字段 | 规则 |
|---|---|
| `timezone` | 本期固定 `Asia/Shanghai` |
| `effective_at` | 任务生效边界，UTC |
| `end_at` | 可选结束边界；必须晚于生效时间 |
| `daily_trigger_time` | 上海时区每日计划触发时间，不含偏移和小数秒 |
| `next_logical_cutoff_at` | 下一计划逻辑截止点；暂停、结束或归档后可为空 |

计划时间决定报告区间，Runner 实际启动时间不改变区间。首次报告是 `(effective_at, first_cutoff]`；失败、补跑和重试仍沿用原计划截止点。

`scheduler`：

| 字段 | 值域/规则 |
|---|---|
| `generation` | 正整数；调度修改递增 |
| `desired_state` | `enabled / disabled / removed` |
| `sync_status` | `pending / synced / drifted / error / not_present` |
| `last_synced_at` | 最近成功或完成校验时间；可为空 |
| `last_error` | 仅 `drifted/error` 必填，且 `stage=scheduler` |

## 5. 状态

任务状态严格为：

- `syncing`：配置已保存，调度同步进行中；`sync_status=pending`；
- `active`：业务任务有效，且调度为 `enabled + synced`；
- `paused`：用户主动暂停，必须有 `paused_at`；
- `scheduler_error`：调度创建、更新或校验失败，`sync_status=drifted/error`；
- `ended`：最终截止点已进入执行链路，不再产生新截止点，必须有 `ended_at`；
- `archived`：默认列表隐藏但保留摘要，必须有 `archived_at`。

调度同步状态不能被任务状态替代。暂停失败报告、Windows 任务漂移等情况必须分别表达业务生命周期与同步事实。

`latest_run.status` 使用 `queued / running / succeeded / partial / failed`。只有 `succeeded/partial` 可以同时出现 `summary + report_ref`；`report_ref` 是不透明公开引用，不是路径或授权凭据。

## 6. 安全

公开任务不得包含 SVN/Windows 凭据、Windows 运行密码、canonical URL、命令参数、物理报告或缓存位置、完整 stderr、原始异常、堆栈、Windows 系统任务 XML。公开错误只使用冻结的 `MonitorPublicErrorPayload`。
