# P3 运维查询与 SVN 缓存契约

> 状态：已实现
> 契约 ID：m2.operations-log-list.v1、m2.svn-cache-status.v1

## 1. 边界

- 原始应用日志属于服务进程，不属于任务结果或结构化任务事件。
- 日志 API 只返回脱敏字段，不返回日志文件路径、凭据、内部路径或异常堆栈。
- SVN 缓存是跨任务共享的全局可再生数据，不记录任务所有权。
- 缓存清理是独立全局动作，不从任务详情发起，不随任务删除或过期执行。
- 正式 m2.diff.v1 结果不是缓存；Replay .m2fixture 不进入查询和清理。

## 2. 运行日志

GET /api/operations/logs

查询参数：

| 参数 | 约束 |
|---|---|
| limit | 1-200，默认 50 |
| cursor | 不透明游标 |
| level | debug / info / warning / error |
| q | 事件、logger 或脱敏消息关键词，最长 128 |
| task_id | 完整 UUID |
| request_id | 完整 UUID |
| created_from / created_to | ISO 8601 时间 |

响应按 created_at DESC, event_id DESC 排序，支持 ETag/304：

~~~json
{
  "schema_version": "m2.operations-log-list.v1",
  "items": [
    {
      "event_id": "00000000-0000-4000-8000-000000000001",
      "created_at": "2026-08-09T10:00:00Z",
      "level": "info",
      "logger": "app.http",
      "event": "http.request",
      "message": "GET /compare/history -> 200 (8ms)",
      "request_id": "00000000-0000-4000-8000-000000000002",
      "task_id": null,
      "process_id": 1234
    }
  ],
  "next_cursor": null,
  "has_more": false,
  "as_of": "2026-08-09T10:00:01Z"
}
~~~

日志文件名包含日期、进程 ID 和大小轮转序号：

excel-merge-YYYYMMDD-p<PID>-NNN.jsonl

写入前和查询时均执行脱敏。异常对象可供进程内诊断，但公开日志记录不序列化 exc_info 或堆栈。

## 3. SVN 缓存状态

GET /api/operations/svn-cache

响应只返回统计，不返回物理目录：

- scope=global_shared
- reproducible=true
- 受管文件数量与总字节数
- 未知项数量，但不返回名称
- 当前服务会话内存命中、磁盘命中、未命中、写入和命中率
- 是否启用及当前是否允许清理

命中计数是服务进程会话指标，重启后归零。磁盘容量来自当前全局缓存目录。

## 4. 全局清理

POST /api/operations/svn-cache/clear

请求：

~~~json
{
  "schema_version": "m2.svn-cache-clear.request.v1",
  "request_id": "00000000-0000-4000-8000-000000000003",
  "confirmation": "清空全局 SVN 缓存"
}
~~~

仅删除当前缓存格式的平面 rev_*__<md5>.bin 文件，并清空当前进程的内存缓存索引。未知文件、子目录、符号链接、任务结果、日志和 Replay 夹具不删除。相同 request_id 在当前进程内幂等返回原结果。

缓存目录为文件系统根、.git、var/m2-batch、var/m2-fixtures 或与排除目录存在父子包含关系时，can_clear=false，清理请求返回 409。
