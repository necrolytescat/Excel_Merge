# `m4.diff-plan-run.v1` 运行与多分支矩阵契约

> 状态：正式契约  
> 日期：2026-08-12

## 1. 启动与冻结

`POST /api/diff-plans/{plan_id}/runs` 接受：

```json
{
  "schema_version": "m4.diff-plan-run-start.request.v1",
  "request_id": "00000000-0000-4000-8000-000000000001",
  "revisions": {
    "Trunk_TC": "HEAD",
    "TC_Fix": 26514
  }
}
```

`revisions` 只能包含计划的基准和目标分支；省略等价于 `HEAD`。HEAD 在创建运行时一次性解析为正整数，运行快照保存计划版本、名称、分支、工作簿和全部具体 Revision。相同 `request_id` 与相同输入直接返回原运行，不重新读取 HEAD。

同一计划只允许一个活动运行。运行创建返回 HTTP 202 和 `m4.diff-plan-run.v1`。

## 2. 状态

运行状态：

- `queued / preparing / running / cancelling`
- `completed / completed_with_failures / cancelled / failed`

执行项身份是 `workbook_path + target_endpoint_id`，最多 40 项。执行项状态：

- `identical`：两侧原始工作簿哈希相同；
- `semantic_equal`：哈希不同，`m2.diff.v1` 工作簿状态为 `unchanged`；
- `changed`：`m2.diff.v1` 工作簿状态为 `modified`；
- `source_missing / target_missing / both_missing`；
- `read_failed / business_failed / orchestration_failed`；
- `queued / running / cancelled`。

哈希只读取计划勾选的工作簿。只有两侧存在且哈希不同的执行项进入 M2 单工作簿执行器。业务失败仍保存原始 `m2.diff.v1` 明细；编排失败不伪造明细。

## 3. 查询与结果

- `GET /api/diff-plans/runs/{run_id}`：完整运行、冻结 Revision、矩阵项和进度；
- `GET /api/diff-plans/{plan_id}/runs`：该计划完整历史摘要；
- `GET /api/diff-plans/run-results/{result_ref}`：原始 `m2.diff.v1`；
- `POST /api/diff-plans/run-results/{result_ref}/export`：使用现有 `m2.export.v1` 决策契约导出该矩阵项的差异 Excel；
- `POST /api/diff-plans/runs/{run_id}/cancel`：`m4.diff-plan-run-command.request.v1`；
- `POST /api/diff-plans/runs/{run_id}/retry`：`m4.diff-plan-run-retry.request.v1`。

重试只接受失败或取消项，创建新的 M4 子运行，复制父运行具体 Revision，不重新解析 HEAD。M4 运行历史不进入 M2 历史任务。

M4 导出不创建新的 Diff 或导出契约。前端在单目标分支、单工作簿明细中复用版本对比导出模式，目标结构固定为该矩阵项的右侧目标分支；服务端从 M4 持久化的原始 `m2.diff.v1` 生成 Excel，不重新访问 SVN。

## 4. 明细保留

终态运行保存 `details_expires_at`。明细默认保留 30 天；计划、运行摘要、冻结 Revision、矩阵状态和重试关系长期保留。过期后运行响应设置 `details_expired=true`，结果引用返回 410 `DIFF_PLAN_RESULT_EXPIRED`。

服务启动时立即清理到期 gzip，运行期间默认每小时扫描一次。物理清理后不删除或改写 `result_ref`，同一引用继续稳定返回 410，不降级为 404。单文件删除失败不改变数据库路径，留待后续周期重试；清理失败不阻断运行调度。
