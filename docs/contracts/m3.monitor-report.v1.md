# `m3.monitor-report.v1` 最终净值报告契约

> 状态：Phase 0 冻结
> 日期：2026-08-10
> Schema：`app/schemas/monitor.py::MonitorReportPayload`

## 1. 业务定义

该契约是离线 HTML 的唯一业务 JSON。报告比较固定分支在 `(start_at, end_at]` 两端的冻结 Table/TableCsv 业务状态，只输出截止时仍存在的最终净变化，再用区间提交回放做字段级归因。HTML 不得再派生第二套业务契约。

`100 -> 120 -> 110` 输出 `100 -> 110`，归因到最后形成 `110` 的提交；`100 -> 120 -> 100` 不输出。一个全局 Revision 同时修改多个分支时，只消费目标规范分支路径的 changed paths。

完整规范示例见 `m3.monitor-report.v1.example.json`；确定性历史样例见 `tests/fixtures/m3_monitor/mock_svn_history.json`。

## 2. 顶层与状态

| 字段 | 规则 |
|---|---|
| `schema_version` | 固定 `m3.monitor-report.v1` |
| `report_id/run_id/task_id` | UUID |
| `task_name` | 报告生成时的公开任务名 |
| `status` | 仅 `succeeded / partial`；完全失败不发布报告契约 |
| `branch` | 与任务相同的固定分支公开身份 |
| `interval` | 左开右闭计划区间，`logical_cutoff_at=end_at` |
| `revisions` | 起止有效分支 Revision，允许相等 |
| `generated_at` | 不早于逻辑截止点的 UTC 时间 |
| `summary/coverage` | 严格统计和覆盖边界 |
| `changes/errors` | 最终净变化与全部可公开错误 |

`partial` 必须存在公开错误或至少一项无法可靠归因；`succeeded` 不得隐藏这两类覆盖缺口。缺失 SVN author 但 Revision/时间仍可靠时使用 `unknown_author`，不自动降级 partial。

## 3. 变化类型和值

变化类型严格为：

- `field_modified`：字段身份非空，source/target 都是 `{display_value, normalized_value}`；
- `row_added`：source 为空，target 是完整 `row_values`；
- `row_deleted`：source 是完整 `row_values`，target 为空；
- `field_added`：source 为空，target 是字段定义；
- `field_removed`：source 是字段定义，target 为空；
- `field_definition_modified`：两侧都是字段定义。

每项都包含 `workbook / sheet_name / primary_key_field / row_key`。字段变化另含稳定 `field_name` 和可选 `display_name`；展示名不是字段身份。字段定义由 `display_name / declared_type / scope` 表示。

业务值来自可靠导出的 TableCsv。`display_value` 保留原始展示字符串；`normalized_value` 是沿用 M2 类型规则的比较依据。行值使用稳定字段名到原始字符串的映射，不使用行号、哈希或模糊匹配作为业务身份。

## 4. 归因

`attribution.status`：

- `attributed`：真实 author、Revision、修改时间齐全；
- `unknown_author`：SVN author 缺失，公开 `author=未知`，但保留真实 Revision 和时间；
- `unresolved`：无法可靠连接事件，`author=未知` 且 Revision、时间、提交说明均为空，报告必须为 partial。

已有字段使用最后一次形成截止值的字段事件；新增行使用创建事件；删除行使用删除事件；结构变化使用最后形成截止结构的事件。`commit_message` 是可选公开提交说明，不得用文件最后作者替代字段作者，也不得伪造归因事实。

## 5. 摘要与覆盖

`summary.by_change_type` 对六种变化类型逐项计数，和必须等于 `change_count`，并与 `changes[]` 实际内容完全一致。`error_count == len(errors)`，`change_count == len(changes)`。

其余可验证统计也直接由契约内容反算：

- `changed_workbook_count` 是 `changes[]` 中不同工作簿数；
- `sheet_count` 是发生净变化的不同 `(workbook, sheet_name)` 数；
- `changed_row_count` 是不同 `(workbook, sheet_name, row_key)` 数；
- `changed_field_count` 是带 `field_name` 的不同字段变化身份数；
- `author_count` 是 `attributed` 变化中的不同已知作者数，不包含“未知”；
- `unknown_author_count` 和 `unattributed_change_count` 分别等于对应归因状态的变化数；
- `failed_workbook_count` 是 `errors[]` 中带工作簿定位的不同工作簿数；
- `workbook_count` 至少覆盖所有发生变化或失败的工作簿，允许包含比较成功但无净变化的工作簿。

`coverage` 固定：

- `data_source=reliable_table_csv`；
- `compared_scope=exported_business_fields`；
- `interval_semantics=left_open_right_closed`；
- `excluded_content` 必须且仅能各列一次：`scope_none_fields`、`unexported_fields`、`excel_notes`、`formulas`、`styles`、`macros`；
- 统计未知 author、无法归因和失败工作簿数量。

无净变化也生成 `succeeded` 空报告，所有变化计数为 0。部分工作簿解析失败时保留其他可靠结果，以 `partial` 和 `MONITOR_PARSE_FAILED` 表达，不能伪装无变化。

SVN Revision 始终是仓库全局编号。目标分支日志只列目标路径实际出现的 Revision，因此允许因其他分支提交产生编号间隙；确定性 Mock 通过 `revision_numbering` 同时列出目标分支日志编号和其他分支独占编号。

## 6. 规范化与安全

规范序列化固定为 UTF-8、非 ASCII 不转义、两空格缩进、结尾换行；SHA-256 基于该字节序列。变化顺序由实现按工作簿、Sheet、主键、变化类型和字段名稳定排序。

报告契约不含 SVN/canonical URL、凭据、Windows 密码、物理报告或缓存位置、仓库根 Revision 清单、命令行、stderr、原始异常、堆栈或任意内部错误 details。公开错误复用 `m3.monitor-run.v1` 的冻结结构。
