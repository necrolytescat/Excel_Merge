# `m2.batch.v1` D1 验收用例

> 当前基线：`py -3 -m pytest -q` -> `188 passed, 1177 warnings in 8.77s`

本清单是 D2 的冻结验收输入。D2 已用分组契约测试覆盖核心场景，并继续通过原 178 项回归；实施记录见 `docs/M2-05-STAGE-D2-REVIEW-HANDOFF.md`。

## 1. Schema 与身份

| ID | 场景 | 验收断言 |
|---|---|---|
| BATCH-C-001 | 合法创建请求 | HTTP 202；返回严格 `m2.batch.v1`；`task_id` 为服务端 UUID，状态为 `queued` |
| BATCH-C-002 | 任意层级增加未知字段 | HTTP 400 `BATCH_INVALID_REQUEST`；不创建任务 |
| BATCH-C-003 | Revision 为 `HEAD`、字符串、0、负数或布尔值 | HTTP 400；不访问 Provider |
| BATCH-C-004 | 请求含候选列表、本地目录、SVN URL、物理路径或凭据 | 因未知字段返回 HTTP 400；服务端不使用这些值 |
| BATCH-C-005 | 两端点相同 | HTTP 422 `BATCH_ENDPOINTS_MUST_DIFFER` |
| BATCH-C-006 | 端点不存在或已禁用 | 分别返回 404 `BATCH_ENDPOINT_NOT_FOUND` 或 422 `BATCH_ENDPOINT_DISABLED` |
| BATCH-C-007 | 相同 request_id、相同输入顺序重放及并发重放 | 只存在一个 task；首次 202，重放 200，task_id 相同 |
| BATCH-C-008 | 相同 request_id、不同 Revision 或端点 | HTTP 409 `BATCH_IDEMPOTENCY_CONFLICT`；原任务不变 |

## 2. 候选准备与文件级模型

| ID | 场景 | 验收断言 |
|---|---|---|
| BATCH-C-009 | 任务创建后准备候选 | Provider 每侧只使用请求中的具体 Revision；不调用 `info()` 或 `HEAD` |
| BATCH-C-010 | 浏览器展示候选被伪造、遗漏或改状态 | 创建请求不接受候选；任务项由服务端完整重建，结果不受浏览器数据影响 |
| BATCH-C-011 | 两侧同路径且哈希不同 | 生成一个 `modified` 项，排队调用现有单工作簿能力 |
| BATCH-C-012 | 路径仅左、仅右存在 | 分别生成 `left_only/right_only + skipped`，不调用语义 Diff，无 result_ref |
| BATCH-C-013 | 两侧存在且任一读取失败 | 生成 `read_error + skipped`，保留侧别错误码，不伪造成空差异 |
| BATCH-C-014 | 两侧同路径且哈希相同 | 不进入候选清单，不计入 total_items |
| BATCH-C-015 | 候选顺序与指纹 | 相同冻结输入重复准备得到相同 path 顺序、manifest_sha256 和 candidate fingerprint |
| BATCH-C-016 | 候选准备前查询 | items 为空，total_items/ratio 为 null，其余计数为 0 |
| BATCH-C-017 | 零候选 | `preparing -> completed`；total=processed=0，ratio=1.0 |

## 3. 单项结果与进度

| ID | 场景 | 验收断言 |
|---|---|---|
| BATCH-C-018 | 引擎返回 `unchanged/modified` | 单项 `succeeded`；独立保存原样 `m2.diff.v1`；result_ref/sha/size/expiry 完整 |
| BATCH-C-019 | 引擎返回 `partial/failed` | HTTP 编排仍成功；单项 `business_failed`；完整合法结果可由 result_ref 读取 |
| BATCH-C-020 | SVN 物化、任务编排或结果保存异常 | 仅当前项 `orchestration_failed`；无 diff_status/result_ref；其他项继续 |
| BATCH-C-021 | 单项超过 600 秒 | 当前项 `orchestration_failed` + `BATCH_ITEM_TIMEOUT`；临时目录清理；其他项继续 |
| BATCH-C-022 | 混合成功、业务失败、编排失败、跳过 | 各进度计数与 item 状态逐项相等；processed 为五类终态和；ratio 公式成立 |
| BATCH-C-023 | 全部项成功或跳过 | 任务终态 `completed` |
| BATCH-C-024 | 至少一个业务或编排失败，无取消 | 任务终态 `completed_with_failures` |
| BATCH-C-025 | 一个工作簿抛出未预期异常 | 异常被单项边界捕获；后续工作簿仍被领取和执行 |

## 4. 结果读取与权限

| ID | 场景 | 验收断言 |
|---|---|---|
| BATCH-C-026 | 读取成功 result_ref | HTTP 200 body 直接通过 `DiffResultPayload.model_validate()`；无批量包装；ETag 等于结果 SHA-256 |
| BATCH-C-027 | result_ref 格式和内容 | 匹配 `^m2r_[A-Za-z0-9_-]{22}$`；不包含 task/item ID、本地路径、SVN URL 或凭据 |
| BATCH-C-028 | 未知、越权、已过期 ref | 分别返回 404、403、410；响应不暴露是否存在内部文件 |
| BATCH-C-029 | `partial/failed` 结果读取 | 返回完整原始 `m2.diff.v1`，包含可用 Sheet 和原错误；不转为 HTTP 500 |
| BATCH-C-030 | 结果落盘中途崩溃 | ref 在数据库提交前不可见；启动后清除孤立文件，不返回半个 JSON |

## 5. 取消与重试

| ID | 场景 | 验收断言 |
|---|---|---|
| BATCH-C-031 | queued/preparing/running 任务取消 | 命令先持久化，返回 202；任务进入 cancelling；不再领取新项 |
| BATCH-C-032 | 取消时有 running 项 | 不强杀；该项按真实结果收敛；所有未开始项为 cancelled；最终任务 cancelled |
| BATCH-C-033 | 取消后读取已完成结果 | 原 result_ref 仍有效到统一 expires_at |
| BATCH-C-034 | 重复取消命令 | 相同 request_id 幂等；不重复改写时间或状态 |
| BATCH-C-035 | 已终态任务取消 | HTTP 409 `BATCH_TASK_NOT_CANCELLABLE`；终态不改变 |
| BATCH-C-036 | 默认重试 | 只选择 orchestration_failed、cancelled 和 read_error skipped；创建新 task，原任务不变 |
| BATCH-C-037 | 显式重试 business_failed | 允许创建子任务，并填写两级 retry_of ID |
| BATCH-C-038 | 重试 succeeded 或单侧 skipped | HTTP 422 `BATCH_ITEM_NOT_RETRYABLE`；不创建部分任务 |
| BATCH-C-039 | 重试混入未知、重复、他任务 item_id 或超过 500 项 | 整个请求拒绝；不产生子任务 |
| BATCH-C-040 | 重试时替换端点或 Revision | 请求 schema 不接受这些字段；子任务只继承原冻结输入 |

## 6. 持久化、恢复与清理

| ID | 场景 | 验收断言 |
|---|---|---|
| BATCH-C-041 | 服务重启后查询任务 | task_id、item 状态、时间、result_ref 和进度保持一致 |
| BATCH-C-042 | running 项租约过期一次 | 清理临时数据后重新排队；recovery_count=1；attempt_count 在再次领取时递增 |
| BATCH-C-043 | running 项第二次中断 | 单项 `orchestration_failed + BATCH_ITEM_RECOVERY_EXHAUSTED`；其他项继续 |
| BATCH-C-044 | 过期 Worker 迟到提交 | 租约 token 校验拒绝提交；不能覆盖新租约或终态结果 |
| BATCH-C-045 | cancelling 状态重启 | 恢复后继续把未开始项取消，最终进入 cancelled |
| BATCH-C-046 | preparing 状态重启 | 已提交清单直接复用；未提交清单在原 Revision 重建；绝不读取 HEAD |
| BATCH-C-047 | 终态未满 30 天 | 任务和结果可读，清理器不删除 |
| BATCH-C-048 | 到达 expires_at | 先写墓碑，再删除明细；任务和结果返回 410；7 天后墓碑可删除 |
| BATCH-C-049 | 清理单个文件失败 | 保留待重试记录，其他有效任务和结果不受影响 |

## 7. 并发、安全与里程碑

| ID | 场景 | 验收断言 |
|---|---|---|
| BATCH-C-050 | 多任务、多进程同时运行 | 全局 running 工作簿不超过 2；任一 task 不超过 1；计数基于共享租约而非进程内变量 |
| BATCH-C-051 | 数据只读边界 | 执行前后 SVN fixture、Excel 和 CSV 哈希不变；无 SVN 写命令 |
| BATCH-C-052 | TableCsv 读取范围 | 每侧只读取自身 main 映射 CSV；不扫描目录猜归属 |
| BATCH-C-053 | 临时目录隔离 | 每个 item 目录独立，成功、失败、超时、取消和恢复后均清理 |
| BATCH-C-054 | 所有者隔离 | result_ref 不能越权读取；ref 的随机性不能替代授权校验 |
| BATCH-C-055 | D1 修改范围 | D1 只新增/修改 docs；没有生产 schema、调度器、路由、存储或页面接线 |
| BATCH-C-056 | 里程碑 | Roadmap 明确首版单机批量能力归 M2-07，通用/分布式队列与长期报告归 M3 |
| BATCH-C-057 | 全量回归 | D2 新测试通过，且当前 178 项测试全部继续通过 |

## 8. 评审门槛

D1 评审应逐项确认：

- schema 字段和非法组合足以实现严格 Pydantic 校验；
- 任务与单项的所有转换均在状态表中出现；
- `partial/failed` 与编排失败没有合流；
- 取消、重试、恢复和清理不会覆盖已完成结果；
- 并发上限是跨 Worker 的服务级限制；
- M2-07 与 M3 的范围不再冲突。
