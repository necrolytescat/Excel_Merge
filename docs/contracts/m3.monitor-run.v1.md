# `m3.monitor-run.v1` 版本监控运行契约

> 状态：Phase 0 冻结
> 日期：2026-08-10
> Schema：`app/schemas/monitor.py::MonitorRunPayload`

## 1. 身份与区间

一个 Run 唯一对应一个 `task_id + logical_cutoff_at`。系统重复触发和全部重试复用同一个 `run_id`、原区间和原逻辑截止点，不能创建第二份逻辑 Run。

`interval` 明确冻结：

```text
(start_at, end_at]
start_inclusive=false
end_inclusive=true
logical_cutoff_at=end_at
```

`boundary_kind` 仅为 `scheduled / pause / end`。恢复边界只作为下一区间起点，不生成 Run。全部瞬时时间规范为 UTC `Z`；计划截止点而非 Runner 实际时间决定区间。

完整规范示例见 `m3.monitor-run.v1.example.json`。

## 2. 顶层字段

| 字段 | 规则 |
|---|---|
| `schema_version` | 固定 `m3.monitor-run.v1` |
| `run_id/task_id` | UUID |
| `status` | 运行状态，见第 3 节 |
| `interval` | 冻结左开右闭区间 |
| `start_revision/end_revision` | 已发布报告在边界处的有效正整数 Revision；必须同时出现，允许相等；未发布状态不得携带 |
| `attempt_count/attempts` | 数量必须相等；attempt 从 1 开始无间隙递增 |
| `summary` | 已发布报告的轻量统计 |
| `report_ref/report_sha256/report_expires_at` | 仅成功或部分成功完整出现；ref 不透明 |
| `errors` | Run 级公开错误列表 |
| `created_at/started_at/finished_at/updated_at` | UTC 生命周期时间 |

Revision 只表示目标固定分支在边界处的有效冻结状态，不是仓库根目录 Revision 列表；全局编号间隙合法。

## 3. 状态与 attempt

Run 状态严格为：

- `queued`：没有执行时间和报告字段；
- `running`：有 `started_at`，无 `finished_at` 和报告字段；
- `succeeded`：完整发布，可有零变化；
- `partial`：已发布但存在公开覆盖缺口；
- `failed`：未发布本次报告，必须有公开错误。

只有 `succeeded/partial` 同时具有 Revision、`summary`、报告引用、SHA、过期时间和 `finished_at`。`queued/running/failed` 不得包含 Revision 或任何报告元数据；`failed` 因此不能覆盖上一份 latest。

Attempt 状态为 `running / succeeded / partial / failed`，触发原因为 `scheduled / automatic_retry / manual_retry`。自动和人工重试沿用原 Run；最后一个 attempt 必须与 Run 当前状态一致。`failed` attempt 必须有公开错误，`running/succeeded` attempt 不得携带错误；`partial` 可携带公开错误，也可仅因报告内存在 `unresolved` 归因覆盖缺口而保持 `errors=[]`，不得为此伪造错误。Run 顶层 `errors` 必须等于最后一个 attempt 的错误。已发布 Run 的 `summary.error_count` 必须等于顶层错误数。临时错误最多自动重试 3 次的策略属于 Runner，但不会改变本契约身份。

## 4. 公开错误

统一结构：

| 字段 | 规则 |
|---|---|
| `code` | 冻结公开错误码 |
| `stage` | 冻结处理阶段 |
| `message` | 1..512 字符的脱敏摘要，不含控制字符 |
| `retryable` | 严格布尔值 |
| `workbook/sheet_name` | 可选公开业务定位 |

错误码：`MONITOR_SVN_TIMEOUT`、`MONITOR_SVN_AUTH_FAILED`、`MONITOR_BRANCH_BINDING_INVALID`、`MONITOR_CONFIGURATION_INVALID`、`MONITOR_PARSE_FAILED`、`MONITOR_ATTRIBUTION_INCOMPLETE`、`MONITOR_REPORT_PUBLISH_FAILED`、`MONITOR_SCHEDULER_SYNC_FAILED`、`MONITOR_INTERNAL_ERROR`。

阶段：`scheduler / branch_identity / history / snapshot / manifest_parse / csv_parse / diff / attribution / report_publish`。

公开结构没有任意 `details` 字典，避免内部信息旁路进入 API。

## 5. 安全

Run 不返回租约 token、进程 ID、Windows 任务信息、命令行、canonical URL、凭据、物理位置、仓库根日志、完整 stderr、原始异常或堆栈。`report_ref` 不是文件名或权限凭据。
