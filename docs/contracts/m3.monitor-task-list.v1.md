# `m3.monitor-task-list.v1` 版本监控任务列表契约

> 状态：Phase 0 冻结
> 日期：2026-08-10
> Schema：`app/schemas/monitor.py::MonitorTaskListPayload`

## 1. 用途

该契约用于当前监控任务列表、筛选和游标分页。它返回扫描所需的任务、固定分支、调度、最近运行和心跳摘要，不替代 `m3.monitor-task.v1`。

完整规范示例见 `m3.monitor-task-list.v1.example.json`。每一级对象严格拒绝未知字段。

## 2. 响应

| 字段 | 规则 |
|---|---|
| `schema_version` | 固定 `m3.monitor-task-list.v1` |
| `items` | `MonitorTaskListItemPayload[]`，默认空数组 |
| `next_cursor` | 可选、不透明、最长 512 字符的 base64url 风格游标 |
| `has_more` | 严格布尔值 |
| `as_of` | 本页查询快照的 UTC 时间 |

列表项包含：

- `task_id/name/status`；
- 与任务契约相同的公开 `branch/schedule/scheduler`；
- 可选 `latest_run`；
- `last_runner_heartbeat_at`；
- `created_at/updated_at`。

状态、时间、分支、调度和最近运行值域完全复用 `m3.monitor-task.v1`，不得建立第二套列表语义。

## 3. 分页与筛选冻结

后续 API 接线应使用稳定排序 `created_at DESC, task_id DESC`。建议查询参数为 `limit`、不透明 `cursor`、可重复 `status` 和名称/端点关键词 `q`。游标必须绑定规范化筛选条件，不能跨筛选重放；`as_of` 用于说明当前页观察时间，不是逻辑截止点。

默认当前列表可以隐藏 `archived`，但显式筛选时仍可返回。到期报告不导致任务摘要消失；完整报告保留期与轻量任务摘要生命周期分开。

## 4. 安全

列表不返回请求幂等 ID、运行 attempt 明细、报告 SHA、SVN/canonical URL、凭据、Windows 运行身份或密码、系统任务名、物理位置、仓库根 Revision 清单、原始日志、stderr、异常或堆栈。`report_ref` 仅出现在已发布的最近运行摘要中，且必须按所有者再次校验。
