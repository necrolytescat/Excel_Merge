# 版本对比差异导出交互重构交接

## 1. 交接目标

继续处理“版本对比”结果页中的差异数据导出交互。

当前后端导出能力和第一版前端交互已经实现，但实际操作路径过于分散。下一阶段不应重写整个结果页，也不应继续向现有布局堆叠控件，而应在保留既有 Diff 能力的基础上，对“导出交互层”做局部结构性重构。

## 2. 已确认的产品规则

- 一次导出针对一个工作簿，可包含该工作簿内多个 Sheet。
- 工作簿内所有 Sheet 共用同一个目标结构，只能选择左侧或右侧。
- 未选择目标结构前不能选择行。
- 同一主键只能选择一个最终决策：不处理、采用左侧、采用右侧或删除。
- 删除只允许目标侧独有行。
- 默认所有行均为“不处理”。
- 批量操作只作用于当前 Sheet、当前筛选可见行。
- 切换 Sheet 后保留已做决策。
- 已有选择时切换目标结构，必须确认并清空当前工作簿全部 Sheet 的选择。
- 导出结果中第一列为辅助列：`操作 / __action__`。
- `写入`和`删除`保留在同一个业务 Sheet 中，不拆页签。
- 复制写入数据时从 B 列开始；删除行用于提醒用户在目标 Excel Sheet 中人工删除。
- 取值侧缺少目标字段、但目标结构对应行存在原值时，保留该原值，并使用红色背景、白色文字标识。
- 无法补位或无法按目标字段类型解释时，整份工作簿导出失败，不生成部分文件。
- 最终行顺序保持 Diff 结果页的稳定显示顺序，不按点击顺序排列。

## 3. 当前实现

### 3.1 服务端

已新增：

- `app/schemas/diff_export.py`
- `app/services/diff_export_service.py`
- `POST /api/diff/batch-results/{result_ref}/export`

契约：

- 请求：`m2.export.v1`
- 校验错误：`m2.export-validation.v1`

当前服务端从持久化 `m2.diff.v1` 生成 `.xlsx`，不重新访问 SVN，不修改原始 Excel、Diff 结果或批量任务。

导出文件包含：

- `导出说明`页签；
- 每个有选择的业务 Sheet 对应一个页签；
- 两行表头；
- `操作 / __action__`辅助列；
- 写入、删除、补位标识、字段省略说明和类型警告；
- 冻结窗格和筛选范围。

### 3.2 第一版前端

已修改：

- `app/templates/compare_results.html`
- `app/static/compare_results.js`
- `app/static/compare_results_readability.css`

当前交互把导出能力分散在三个位置：

1. 工作簿标题区域选择目标结构；
2. Sheet 差异工具栏执行批量取左、取右和清空；
3. 左右表格行号区域分别显示行选择框和删除选择框。

功能基本成立，但用户需要在多个区域之间来回确认，左右两套勾选框也让“同一主键只能有一个最终决策”不够直观。

## 5. 下一阶段设计结论

采用“保留结果页基础能力，重构导出交互层”的方案。

不重写：

- Diff 数据契约和映射；
- 左右表格、虚拟滚动和滚动同步；
- 工作簿、Sheet 导航；
- 正式结果和 Replay 基础运行方式；
- 已实现的导出 API 与 Excel 生成服务。

重点重构：

- 导出入口；
- 目标结构选择；
- 行级最终决策；
- 当前 Sheet 批量操作；
- 跨 Sheet 汇总；
- 校验和导出反馈。

## 6. 推荐交互结构

### 6.1 普通查看模式

- 默认保持纯差异查看状态。
- 不显示行级导出勾选框。
- 提供单一入口“导出差异数据”。

### 6.2 导出模式

- 点击入口后进入显式导出模式。
- 首先选择工作簿级目标结构：左侧或右侧。
- 每个主键只显示一组统一决策控件：
  - 不处理；
  - 采用左侧；
  - 采用右侧；
  - 删除。
- 决策控件应位于独立的“导出决策列”或左右数据之间，不能继续分散在左右行号旁。
- 不存在的数据侧禁用；删除仅在目标侧独有行启用。

### 6.3 汇总与提交

- Sheet 导航显示写入数、删除数和错误数。
- 当前 Sheet 保留“全部取左侧、全部取右侧、清空选择”，但必须只处理当前筛选可见行。
- 页面底部使用固定操作栏显示：
  - 已选写入数；
  - 删除数；
  - 校验错误数；
  - 取消导出；
  - 校验并导出。

## 7. 推荐代码边界

- 将导出状态和交互从 `compare_results.js` 拆分为独立模块，例如 `compare_results_export.js`。
- 主结果页只提供稳定的工作簿、Sheet、筛选状态和行渲染挂载点。
- 导出模块负责目标结构、行决策、批量范围、汇总、请求组装和错误定位。
- 不改变后端接口，除非在验收中发现当前契约确实无法表达已确认规则。
- 不更新黄金 Replay 夹具，除非获得明确授权。

## 8. 建议实施顺序

1. 先检查正式结果页和 Replay 的现有渲染、筛选与虚拟滚动结构。
2. 为导出模式设计最小 DOM 挂载点和模块边界。
3. 把现有导出状态逻辑迁出 `compare_results.js`，迁移过程中保持行为不变。
4. 引入普通模式/导出模式切换。
5. 将左右行内勾选框改为单一主键决策控件。
6. 修正批量操作范围为当前 Sheet、当前筛选可见行。
7. 增加固定汇总操作栏、跨 Sheet 状态和错误定位。
8. 运行专项测试、全量测试、Node 静态检查和浏览器验收。

## 9. 工作区注意事项

- 当前导出实现仍是未提交修改，新任务应基于当前 working tree 继续，不能从干净分支重新开始。
- 工作区存在用户自己的未跟踪文件 `新对话.txt`，不要修改、删除或纳入实现。
- 维护“版本对比”前必须先阅读 `docs/VERSION-COMPARISON-HANDBOOK.md`。
- `m2.diff.v1`、source/target 语义和 SVN 只读边界保持不变。

## 10. 新任务的完成标准

- 用户不进入导出模式时，结果页保持清晰的差异查看体验。
- 用户进入导出模式后，始终围绕“一个主键、一个最终决策”操作。
- 目标结构、批量范围、跨 Sheet 状态和导出反馈符合第 2 节规则。
- 不回归现有 Diff 查看、正式批量结果、Replay 和 M4 运行能力。
- 后端导出专项、前端契约、全量测试和浏览器验收全部通过。
