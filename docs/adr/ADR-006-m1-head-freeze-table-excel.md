# ADR-006：M1 确认时冻结 HEAD，只读取 Table 全量 Excel

- 状态：已接受并实施（M1 已归档）
- 日期：2026-08-04
- 范围：M1 版本对比快照

## 背景

版本负责人会在版本日锁定两个具体端点，例如 `FIX1.1.0` 与线上 `fix1.0.0`，然后确认两端当前状态。日期选择会引入“日期对应哪一次提交”、时区和延迟执行歧义；手工 Revision 也不应成为业务端点配置的一部分。

## 决策

1. 页面只让用户选择两个已注册端点 ID；
2. 点击确认时分别读取当前 HEAD，并立即记录解析出的具体 Revision；
3. 后续列目录、读文件全部使用冻结 Revision；
4. 逻辑读取范围固定为 `Table`，递归包含 `.xlsx`、`.xlsm`、`.xls`；
5. M1 不读取其他目录、CSV 或 TBX，不解析工作簿；快照可筛选文件级差异候选，但不执行 Sheet/单元格 Diff 和 SVN 写操作；
6. Revision 只出现在快照元数据和文件清单中，不出现在端点配置和用户输入中。
7. 确认后将本次解析出的 Table 物理路径绑定回端点注册表；文件级差异候选作为后续 Excel Diff 任务的输入。

## 影响

- 已确认的快照可按 Revision 复现，即使分支之后继续提交；
- 如果用户希望代表过去某个时刻，必须在当时点击确认并冻结，不能依赖事后日期查询；
- 延迟执行需要后续专用快照存储或固定端点能力；
- 后续 Diff 引擎消费二进制快照，不改变 M1 契约。
## 实施结果

- 归档日期：2026-08-05；
- 真实 KR FIX 两端各读取 197 个 Excel，筛选出 53 个文件级差异候选；
- Table 物理路径已绑定为 `Source/table`；
- 全量测试：114 passed。
