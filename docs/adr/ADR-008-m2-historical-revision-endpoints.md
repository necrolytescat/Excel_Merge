# ADR-008：版本对比支持历史 Revision 端点

> 状态：已接受并实施
> 日期：2026-08-12
> 范围：版本对比端点选择、快照与批量任务

## 背景

ADR-006 将端点确认定义为冻结当前 HEAD，ADR-007 要求一个端点数据集中的
`Table` 与 `TableCsv` 来自同一端点、同一冻结 Revision。版本负责人还需要在
分支继续提交后回看历史版本，并在同一分支的两个历史状态之间执行对比。

把 Revision 写入端点注册表会混淆“分支身份”和“一次对比选择”，按日期查询则
存在时区和提交边界歧义。因此 Revision 应是一次快照请求的临时输入，并继续在
服务端解析和冻结。

## 决策

1. 左右端点仍选择已登记或可登记的分支；每侧 Revision 默认值为 `HEAD`。
2. 用户可从当前分支的提交 LOG 中显式选择正整数 Revision，不接受日期、0、
   负数、布尔值或其他字符串。
3. `HEAD` 在快照创建时只解析一次，之后所有目录与文件读取统一使用解析出的
   具体 Revision；显式 Revision 不调用 HEAD。
4. 同一端点可用于左右两侧，但最终解析 Revision 必须不同。选择阶段相同组合
   由前端拒绝；HEAD 与历史值解析相同等情况由快照服务再次拒绝。
5. 分支 LOG 查询必须以所选分支 URL 为目标，按 Revision 降序分页，并在分支
   copy 创建点停止；不得先读取仓库全量历史或混入其他分支提交。
   LOG 选择辅助信息包含 Revision、提交人、提交时间和 Message。
6. 历史 Revision 下若注册表中的 `TABLE` 路径不存在，服务端必须在该 Revision
   重新发现；找不到时明确失败，不生成空快照。
7. 只有 HEAD 快照发现的 `TABLE` 路径可写回全局端点注册表。历史路径只属于
   本次任务，不能覆盖当前分支绑定。
8. 单工作簿物化继续从同一端点、同一具体 Revision 读取 Excel、`main` 和
   同级 `TableCsv`，并采用与快照一致的历史 `TABLE` 路径回退规则。
9. 比较方向继续固定为 `source=left`、`target=right`；SVN 仍为只读，
   `m2.diff.v1` 与 `m2.batch.v1` 的结果结构不变。

## 对既有 ADR 的修订

- 对 ADR-006 第 1、2、6 项作局部修订：页面现在允许为一次对比显式选择
  Revision；未选择时仍冻结 HEAD，Revision 仍不属于端点配置。
- 对 ADR-007 第 2 项作局部修订：用户不单独选择 CSV 端点，但可选择端点
  Revision；`Table` 与 `TableCsv` 的同端点、同 Revision 约束保持不变。
- ADR-006、ADR-007 的其他结论继续有效，不改写其历史文本。

## 影响

- 同一分支的任意两个不同 Revision 可以复现式对比。
- 分支 LOG 是选择辅助信息，不进入 Diff 结果，也不改变 Replay 黄金夹具。
- 批量创建请求继续只接受服务端快照返回的正整数 Revision，不接受 `HEAD`。
- 结果页必须同时显示分支名与最终 Revision，避免同分支历史对比产生歧义。
