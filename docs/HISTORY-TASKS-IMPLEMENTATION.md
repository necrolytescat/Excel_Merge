# “历史任务”分阶段实施文档

> 状态：P1-P3 已交付
> 日期：2026-08-09
> 范围：左侧导航“结果”分组、批量任务列表、正式结果恢复及后续治理边界
> 真实历史数据验收：已通过

> 后续维护入口：`docs/HISTORY-TASKS-HANDBOOK.md`

## 1. 目标

“历史任务”用于总览版本对比的历史任务和实时进度，并重新进入任意仍在保留期内的任务。关闭网页或标签页不会停止后端任务；重新打开进行中任务时必须挂接原 Task ID，终态任务必须读取既有结果，任何恢复操作都不得创建重复任务。

## 2. 不可突破的边界

- 保持 `m2.diff.v1`、`m2.batch.v1` 及 `source=left`、`target=right` 不变。
- 保持两侧独立冻结 Revision、Excel 与 TableCsv 同侧同 Revision、SVN 只读。
- 不修改 `core/` 解析、配对、主键或 Diff 语义，不新增第二套前端 Diff JSON。
- 列表只返回任务摘要；工作簿明细继续通过现有任务查询和 `result_ref` 按需读取。
- 正式任务结果是保留期内的正式产物，不是缓存。
- SVN 内容缓存是跨任务共享的全局可再生数据，任务过期或删除不得触碰。
- Replay 夹具是回归资产，不进入正式任务列表和任何自动清理。

## 3. 分阶段交付

### P1：历史任务恢复

- 用“历史任务”替换全部“任务与报告”禁用入口，新增 `/compare/history`。
- 新增 `m2.batch-list.v1` 列表 API，支持游标分页、状态、关键词和创建时间筛选。
- 列表展示 Task ID、左右端点与冻结 Revision、状态、进度、时间和到期时间。
- 活动任务页面可见时自动刷新；终态页低频刷新，并支持手动刷新。
- 正式结果地址使用 `/compare/results?task_id=<UUID>`；URL Task ID 优先于 `sessionStorage`。
- 进行中任务只调用 GET 并挂接现有轮询；完成任务读取既有结果。
- 保留裸 `/compare/results` 的旧会话兼容；重试子任务同步替换 URL。
- 任务到期后立即返回 410，不等待后台清理周期；墓碑期结束后返回 404。

### P2：任务事件与正式结果管理

- 已新增独立的结构化任务事件表，记录状态转换、命令、恢复和可公开错误。
- 事件通过 Task ID 关联，但不写入 `m2.batch.v1`，不复制 `m2.diff.v1` 明细。
- 历史任务详情展示任务时间线、正式结果数量/大小/到期时间和重试关系。
- 仅允许手动删除终态任务；逻辑删除立即生效，物理删除仅限该任务正式结果。
- 父任务和重试子任务独立删除，不级联；结构化事件默认保留 90 天，可独立配置。
- 新表由 SQLite 初始化幂等创建，不改写现有 `tasks/items` 表，无需离线数据库迁移。

### P3：日志与全局缓存治理

- 已实现按进程、日期和大小独立轮转的 JSONL 应用日志，通过 Task ID/request ID 做相关性检索。
- 日志写入前和查询时双重脱敏，不返回凭据、内部路径、日志路径或异常堆栈。
- 已实现 SVN 全局缓存容量、文件数、会话命中率、内存索引和可再生状态。
- 缓存清理使用独立全局确认与幂等 request ID，不能从某个任务发起或按任务归属删除。
- 清理只识别当前 rev_*__<md5>.bin 缓存格式；未知项、正式结果、日志和 Replay 始终排除。

## 4. P1 页面与交互

历史任务页使用适合扫描的表格布局。默认按 `created_at DESC, task_id DESC` 排序，包含“全部、进行中、已完成、需关注”状态分组、Task/端点搜索、创建时间范围、手动刷新和“加载更多”。

页面状态包括：首次加载、正常列表、无历史任务、筛选无结果、刷新失败但保留旧数据、服务不可用。活动任务显示进度条和处理数，操作按状态显示“查看进度”“查看结果”或“查看详情”。

自动刷新规则：页面可见且当前列表包含活动任务时每 2 秒刷新；无活动任务时每 15 秒刷新；页面隐藏时暂停。服务端使用 ETag/304 减少重复数据传输。

## 5. URL 恢复

1. 新任务创建成功后跳转 `/compare/results?task_id=<task_id>`。
2. 结果页先解析并校验 URL Task ID，再读取 `sessionStorage` 作为兼容回退。
3. URL Task ID 存在时，浏览器候选不是权威输入；结果页通过 `GET /api/diff/batches/{task_id}` 重建端点、Revision、候选与结果引用。
4. 重试创建子任务后使用 `history.replaceState` 更新 Task ID。
5. 410 显示“任务已过期”，404 显示“任务不存在”，不得自动创建替代任务。

## 6. 生命周期

| 数据 | 所有权 | 生命周期 |
|---|---|---|
| 批量任务元数据与正式 gzip 结果 | 单任务 | 终态 30 天，墓碑 7 天 |
| 结构化任务事件 | 任务关联、独立存储 | P2 独立配置，不随结果文件直接删除 |
| 原始应用日志 | 服务进程/实例 | 按时间和大小轮转，不随任务删除 |
| SVN 落盘及快照内存缓存 | 全局共享 | 可再生；只允许全局治理 |
| Replay `.m2fixture` | 版本化回归资产 | 不自动清理 |

## 7. P1 验收标准

- 清空 `sessionStorage` 后仍能从历史任务打开活动任务和终态任务。
- 打开活动任务不会新增任务记录或调用创建 API，服务重启后仍能继续恢复。
- 完成、部分失败、取消、失败、零候选任务均有明确状态。
- 游标分页无重复或遗漏，筛选和 ETag 行为稳定。
- 到期任务立即返回 410，墓碑结束后返回 404，活动任务不按年龄过期。
- 任务列表和结果恢复不返回内部结果路径、SVN URL、凭据或堆栈。
- 任务过期测试确认 `.cache/svn`、日志和 Replay 夹具不受影响。
- 全量测试、JavaScript 语法检查和桌面/移动端浏览器验收通过。

## 8. P2 验收标准

- 管理详情使用 `m2.batch-management.v1`，支持 ETag/304，不扩充 `m2.batch.v1`。
- 时间线包含创建、状态转换、命令、恢复和可公开错误；旧任务从权威时间戳补充最小基线。
- 正式结果统计只返回数量、规范 JSON 字节数和到期时间，不返回 `result_ref` 或内部路径。
- 活动任务删除返回 409；终态删除按 `request_id` 幂等，删除后任务和结果立即返回 410。
- 删除父任务不会删除重试子任务；删除子任务也不会修改父任务。
- 删除只清理该任务正式 gzip 结果；测试确认 SVN 共享缓存、原始日志和 Replay 夹具不受影响。
- 结构化事件默认保留 90 天并通过 `batch_diff.event_retention_days` 独立配置。
- 桌面与移动端详情布局、URL `detail` 恢复、错误状态和删除确认通过浏览器验收。

## 10. P3 验收标准

- 历史任务页提供“任务记录 / 运行日志 / SVN 缓存”三个独立视图，URL view 可恢复当前视图。
- 日志支持级别、关键词、时间、Task ID、request ID、游标分页与 ETag；页面只渲染脱敏契约。
- 日志文件按“日期 + PID + 大小序号”独立轮转，保留期和扫描上限可配置。
- 缓存页不展示物理目录和任务归属，只展示全局容量、文件数、会话命中与可再生状态。
- 全局清理要求输入固定确认文本；重复 request ID 幂等。
- 隔离缓存清理验证未知文件、正式结果样本、应用日志和 Replay 样本不受影响。
- 任务删除、过期和缓存清理三条生命周期互不联动。
