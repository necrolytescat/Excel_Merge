# M3 版本监控需求基线

> 状态：需求已对齐，等待实施计划评审
> 更新日期：2026-08-10
> 模块名称：版本监控

## 1. 背景与目标

版本监控面向 QA 的每日快速回归。用户为一个固定 SVN 分支建立监控任务，系统在约定截止点生成该分支自上一个逻辑截止点以来的业务字段最终净值变化报告。

模块必须满足：

- Web 页面或 FastAPI 进程关闭后，已配置任务仍可由 Windows 计划任务触发；
- SVN 全链路只读，不执行 checkout、update、commit、merge、copy 或写回；
- 报告只覆盖可靠导出的 TableCsv 业务字段，并沿用版本对比模块的配对和语义规则；
- 每份报告区间确定、可重跑、无重复、无遗漏；
- 报告是独立长期业务产物，不复用 M2 批量任务、应用日志或 SVN 缓存作为存储。

## 2. 范围

### 2.1 本期范围

- 左侧导航新增“版本监控”；
- 创建固定分支的每日监控任务；
- 配置任务生效时间、结束时间和每日触发时间；
- 使用 Windows 计划任务独立触发报告 Runner；
- 生成最终净值变化的单文件离线 HTML；
- 展示全部当前监控任务及调度、运行、报告状态；
- 支持暂停、恢复、修改调度、失败重试、结束和归档；
- 断网、注销或关机导致的遗漏报告可补跑；
- 历史完整报告保留 30 天。

### 2.2 非目标

- 不展示区间内每一次中间改动；
- 不比较 Excel 物理单元格、样式、公式、宏或 `scope=none` 字段；
- 不生成 Excel、PDF 或邮件附件；
- 不发送邮件、IM 或其他通知；
- 不支持多节点调度、分布式 Worker、权限或配额；
- 不执行 Excel Merge 或 SVN 写回；
- 不允许用户选择任意物理报告目录。

## 3. 核心术语

| 术语 | 定义 |
|---|---|
| 固定分支 | 创建任务时绑定的已注册 SVN 端点，由仓库 UUID、规范 URL 和仓库相对路径共同标识 |
| 逻辑截止点 | 决定报告区间边界的时间，可由每日触发、暂停或任务结束产生 |
| 计划触发点 | 按任务时区和每日触发时间计算的逻辑截止点，不等于 Runner 实际启动时间 |
| 报告区间 | 左开右闭的 `(上一个逻辑边界, 本次逻辑截止点]` |
| 最终净值变化 | 区间起始快照和截止快照之间仍然存在的业务差异 |
| 最终修改人 | 区间内最后一次把该字段设置为截止值的 SVN 提交人 |
| 遗漏执行 | 计划触发时用户注销、电脑关机或 Runner 未运行，之后按原计划截止点补生成 |

## 4. 用户流程

### 4.1 创建任务

1. 用户进入“版本监控”；
2. 输入任务名称；
3. 从已启用端点注册表选择一个固定分支；
4. 设置生效时间、结束时间和每日触发时间；
5. 系统验证分支身份、数据布局、时间范围和历史回溯限制；
6. 系统保存任务并同步创建对应的 Windows 计划任务；
7. 同步成功后任务进入“运行中”，失败则进入“调度异常”。

历史开始时间最多早于创建时间 30 天，且不得早于分支创建时间。已经到期的截止点在任务创建后按时间顺序补生成。

### 4.2 每日运行

1. Windows 计划任务在用户设置的每日时间启动独立 Runner；
2. Runner 按 Task ID 读取数据库中的当前权威配置；
3. Runner 创建或抢占本次逻辑截止点对应的运行记录；
4. Runner 解析分支区间 Revision、读取冻结数据并计算最终净值变化；
5. Runner 生成历史 HTML，成功发布后原子更新 `latest.html`；
6. 任务列表显示本次状态、变化统计和报告入口。

### 4.3 查看任务

二级页面显示全部当前任务，至少包含：

- 任务名称和固定分支；
- 生效时间、结束时间、每日触发时间；
- 业务状态和 Windows 调度同步状态；
- 上次报告区间、运行状态和变化数量；
- 下一次逻辑截止点；
- 最近 Runner 心跳；
- 最新报告入口；
- 暂停、恢复、修改调度、重试、结束和归档操作。

## 5. 时间与区间规则

### 5.1 基本区间

正常日报使用：

```text
(上一次计划触发点, 本次计划触发点]
```

- 边界左开右闭；
- 正好发生在截止点的提交进入本次报告；
- 使用计划时间，不使用 Runner 实际启动时间；
- 默认且本期唯一时区为 `Asia/Shanghai`；
- 无净变化也生成成功报告。

首次报告使用：

```text
(任务生效时间, 第一个计划触发点]
```

如果任务结束时间落在两个计划触发点之间，结束时间成为最终截止点：

```text
(上一个逻辑截止点, 任务结束时间]
```

结束时间正好等于计划触发点时只生成一份报告。

### 5.2 失败不改变区间

逻辑边界由任务计划决定，不依赖上一份报告是否成功。例如 8 月 10 日报告失败，8 月 11 日报告仍只覆盖：

```text
(8月10日 18:00, 8月11日 18:00]
```

之后重试 8 月 10 日报告时仍使用其原始区间。不同日期报告不会因失败而重叠。

### 5.3 修改触发时间

修改每日触发时间不回写既有逻辑边界。下一份报告从修改前最后一个逻辑边界开始，到修改后第一个有效计划触发点结束。区间可能长于或短于 24 小时，但不能重复或遗漏。

### 5.4 暂停与恢复

- 用户主动暂停与系统遗漏执行含义不同；
- 暂停时间成为临时截止点，生成暂停前的最后一份不足一天报告；
- 暂停期间不生成报告，也不在恢复后补算；
- 恢复时间成为新的无报告起始边界；
- 下一份报告使用 `(恢复时间, 下一个计划触发点]`；
- 暂停截止报告失败不阻止任务进入暂停状态，但必须保留失败提示和重试入口。

### 5.5 注销、关机与补跑

- 浏览器、Web 服务关闭或屏幕锁定不影响已注册 Windows 任务；
- 用户注销或电脑关机时不能执行；
- 重新登录后按遗漏的计划截止点依次补跑；
- 补跑仍使用原计划截止时间，不吸收截止时间之后的提交；
- 运行身份固定为创建任务的当前 Windows 用户，不保存 Windows 登录密码。

## 6. SVN 分支与 Revision 规则

SVN Revision 编号是仓库全局编号，无法变成分支内独立连续编号。M3 的正确约束是只接受和展示固定分支路径历史中实际出现的 Revision。

创建任务时保存：

- `endpoint_id`；
- `repository_uuid`；
- `canonical_url`；
- `repository_relative_path`；
- 创建时验证到的分支 Revision 和复制边界。

固定分支创建后不可修改；更换分支必须新建任务。Runner 每次执行重新校验端点注册表和冻结身份，发现 URL、仓库 UUID 或相对路径变化时停止运行并报告绑定失效。

CLI 能力基线为 SVN 1.14.3：

```text
svn info --xml <branch-url>
svn log --xml -v --stop-on-copy -r <start>:<end> <branch-url>
svn cat <branch-url>/<path>@<revision>
```

SVN 日志返回后仍必须：

- 按提交时间做精确时区边界过滤；
- 按仓库相对分支前缀做分段匹配，不能使用不安全的字符串前缀；
- 排除同一 Revision 中分支外 changed paths；
- 使用复制边界，不能追溯到源分支历史；
- 不向页面返回凭据、仓库根目录日志或物理缓存路径。

## 7. 数据与差异语义

M3 沿用当前版本对比模块的稳定业务规则：

- Excel `main` 清单负责 `sheetName`、`tbxName` 和 `isExport` 配对；
- Table Excel 与 TableCsv 必须来自同一固定分支和同一冻结 Revision；
- 业务值只来自可靠导出的 TableCsv；
- `scope=none` 字段不参与比较；
- 主键沿用 `Id/id` 大小写不敏感唯一匹配及现有第一列兜底；
- 字段身份使用稳定 `field_name`，展示名仅作元数据；
- 类型规范化沿用整数、小数、布尔、日期和时间规则；
- 不使用行号、内容哈希或模糊相似度匹配业务行。

“所有字段修改”仅指所有可比较 TableCsv 业务字段。报告必须明确提示未导出字段、Excel 备注、公式、样式和宏不在覆盖范围内。

## 8. 最终净值与归因

报告先比较区间起始与截止快照，再为仍然存在的最终差异回放区间提交并归因。

示例：

- `100 -> 120 -> 110`：报告显示 `100 -> 110`，最终修改人为把值设为 110 的提交人；
- `100 -> 120 -> 100`：最终无净变化，不进入报告；
- 文件最后提交人没有修改目标字段时，不能错误归因为该文件最后提交人。

归因规则：

- 已有行字段修改：记录最后一次形成截止值的字段级提交人、Revision 和时间；
- 净新增行：记录行创建人，并允许各最终字段记录自己的最后修改人；
- 净删除行：记录删除该主键行的提交人；
- 字段新增、删除或定义变化：记录最后形成该结构状态的提交人；
- 缺失 SVN author 时显示“未知”，并在报告覆盖提示中计数；
- 无法可靠归因但可计算净值时，报告状态为“部分成功”，不能伪造作者。

## 9. 报告产物

第一版唯一用户报告格式为单文件离线 HTML。HTML 内嵌样式、脚本和报告数据，不依赖正在运行的 Web 服务。

目录结构：

```text
var/m3-monitor/reports/<task_id>/
|-- latest.html
`-- history/
    |-- 20260810-180000.html
    `-- 20260811-180000.html
```

规则：

- 历史文件按逻辑截止点命名，发布后不可变；
- `latest.html` 只在报告完整发布后原子替换；
- 成功、无变化和部分成功报告可更新 `latest.html`；
- 完全失败或文件发布失败不得覆盖上一份 `latest.html`；
- 数据库保存相对路径、文件 SHA-256、规范结果引用和运行摘要；
- 文件路径不使用分支名或其他用户输入；
- Web 页面通过受控 API 打开报告，不公开物理系统路径。

报告至少包含：

- 任务、分支、报告区间、计划截止时间、起止有效 Revision 和生成时间；
- 工作簿、Sheet、主键字段和值；
- 变更类型、字段展示名、字段名、起始值和截止值；
- 最终修改人、最终 Revision、最终修改时间和提交说明；
- 工作簿、Sheet、行、字段、作者和错误统计；
- 按工作簿、Sheet、提交人、变更类型筛选及主键搜索；
- 数据覆盖边界和全部可公开错误摘要。

## 10. 状态模型

任务状态：

- `syncing`：正在同步 Windows 计划任务；
- `active`：业务任务和系统调度均有效；
- `paused`：用户主动暂停；
- `scheduler_error`：系统任务创建、更新或校验失败；
- `ended`：最终截止报告已进入执行链路且任务不再产生新截止点；
- `archived`：从当前任务默认列表隐藏，但保留历史摘要和未过期报告。

运行状态：

- `queued`；
- `running`；
- `succeeded`；
- `partial`；
- `failed`。

调度同步状态与业务任务状态必须分开保存，不能用一个字符串掩盖 Windows 任务漂移或权限失败。

## 11. 失败与重试

- SVN 超时、临时网络错误和报告文件占用：每 10 分钟自动重试，最多 3 次；
- SVN 认证失败、分支绑定失效、配置错误和确定性解析错误：不自动重试；
- 所有重试复用原运行记录、原始区间和逻辑截止点，并单独记录 attempt；
- 部分工作簿失败时生成“部分成功”报告并更新 `latest.html`，顶部必须醒目标注数据不完整；
- 完全失败时保留上一份 `latest.html`，任务列表提供按原区间重试入口；
- 某个截止点失败不阻塞后续截止点独立执行。

## 12. 存储与保留

- M3 使用独立 SQLite 和报告目录，不复用 `var/m2-batch`；
- 建议状态根目录为 `var/m3-monitor/`；
- 完整历史 HTML 和规范结构化结果保留 30 天；
- 过期后保留轻量运行摘要、状态、统计和文件哈希；
- `latest.html` 在任务被彻底删除前保留；
- 活动任务不能彻底删除，只能暂停或结束；
- 已结束或归档任务的彻底删除必须二次确认，只删除该任务 M3 数据；
- 删除不得触碰 M2 任务、应用日志、SVN 缓存、Replay 夹具或其他监控任务。

## 13. 验收标准

### 13.1 调度

- 每个监控任务对应一个 Windows 计划任务，不使用分钟级轮询；
- Web 和 FastAPI 关闭后，登录用户会话中的计划任务仍可生成报告；
- 系统重复触发同一截止点不会产生重复运行或重复文件；
- 注销或关机后重新登录，可按原截止点补齐 30 天内遗漏报告；
- 暂停期间不补跑，恢复后从恢复时间重新建立区间。

### 13.2 SVN 与语义

- 混合修改多个分支的同一 Revision 只报告固定分支内容；
- 分支 Revision 可有全局编号间隙，页面不得混入仓库根目录其他 Revision；
- 修改后回退到起始值不进入报告；
- 字段最后作者按字段事件归因，不能退化为文件作者；
- TableCsv 配对、主键、类型和 scope 规则与 M2 一致；
- 任一 SVN 操作均为只读。

### 13.3 报告与治理

- HTML 可在 Web 服务关闭时离线打开；
- 历史报告不可变，`latest.html` 原子更新；
- 部分成功和完全失败不会被伪装成成功；
- 30 天过期清理不删除 `latest.html` 或轻量运行摘要；
- 页面和 API 不暴露凭据、物理报告路径、缓存路径或内部堆栈。
